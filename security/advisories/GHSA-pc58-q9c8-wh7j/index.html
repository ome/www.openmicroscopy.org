Synopsis

XSS vulnerability when removing user

Background

When an administrator attempts to remove a user from their only group, the action fails with an error message that contains the user's first and last name. Those values are not HTML encoded, so they provide a vector for executing code within the administrator's browser session. Possible actions include creating additional administrator accounts with known usernames and passwords. For a successful exploit, a user must already have an account in OMERO and change their first and last names for the account to the desired malicious code. They also must be member of only a single group and then get an existing administrator to attempt to remove them from that group.

Affected Packages

OMERO.web <=5.33.2

Impact

High severity.

Resolution

All OMERO.web deployments should be upgraded to at least 5.33.3.
